# Bootstrap｜项目启动协议

任何新项目或恢复项目，都先运行本协议，再选择策略原子。启动的目标是自动接上用户的 Chrome 与灵光主会话；它不尝试读取 Cookie、凭证或任何浏览器存储。

## 输入与记录

先读取项目已有的 `project-session.md`；没有时从模板创建。最低项目输入为：品牌/产品或研究对象、要回答的业务问题。商业类目、时间范围、卖点和场景可后补，但必须在进入相应原子前补齐。

## 启动状态

| 状态 | 可观察条件 | 动作 |
| --- | --- | --- |
| `ready` | 已发现可访问、已登录的灵光标签或已成功续接主会话 | 写入主会话描述与当前页面，继续最小原子。 |
| `login-required` | 灵光页面可打开，但页面要求登录、验证码或授权 | 停在该页面，请用户完成登录并告知“已完成”；不绕过。 |
| `browser-unavailable` | Chrome 控制不可用、扩展未连接或浏览器未启动 | 告知用户在 Codex 设置中连接 Chrome；不改用其他登录态。 |
| `project-input-required` | 没有品牌/对象或没有业务问题 | 只询问缺失的最小字段；不先猜测类目。 |
| `entry-url-required` | 没有灵光标签，且项目会话与用户配置中都没有已确认的官方入口地址 | 请求一次官方入口地址；保存为非敏感地址，供后续项目自动打开。 |

## 决策顺序

1. 如果 `project-input-required`，先补项目对象与问题。
2. 使用 `$chrome:control-chrome` 只读检查 Chrome 当前标签与可见登录状态。
3. 若发现同项目主会话，优先续接；若发现其他灵光会话，观察后决定是否能安全复用。
4. 没有灵光标签但已有确认入口地址时，在当前 Chrome 正常打开该地址。
5. 若出现 `login-required` 或 `browser-unavailable`，停止任务提交；可继续整理本地资料和研究计划。
6. 仅当状态为 `ready` 时，才进入 `explore`、`collect`、`validate`、`assemble` 或 `deliver`。

## 会话识别

记录可见会话标题、页面路径、最近任务描述和最后检查时间；不记录账号名、Cookie、令牌、会话 ID 或页面隐藏参数。项目内默认只维护一个灵光主会话。

## 恢复规则

如果会话中已有未完成任务，先检查该任务，而非重新提交。连续两次检查没有状态变化时，更新任务卡为停滞，并只尝试一次最小替代验证。
